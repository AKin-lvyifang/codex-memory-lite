# Codex Memory Lite V2 如何工作

[English](how-it-works.md)

V2 把观察、判断、校验和写入拆成四层。模型可以判断什么值得记，但不能直接覆盖长期记忆。

## 五个组成部分

### 1. 项目初始化 Hook

第一次收到 `UserPromptSubmit` 时，Hook 会从当前目录向上查找 Git 根目录或常见项目标记，并跳过系统目录、临时目录、Codex 自身目录和明确排除的项目。

如果项目还没有 V2 manifest，会自动登记项目并执行其中一个动作：

- 新项目执行 `bootstrap`
- 已存在 `.codex-memory/current.md` 时执行 `migrate-v1`

这个过程不会创建或修改项目 `AGENTS.md`。

### 2. 事件 Hook

主 Hook 观察以下生命周期节点：

| 事件 | V2 的动作 |
| --- | --- |
| `SessionStart` | 恢复中断事务、建立工作区基线、处理已有积压 |
| `UserPromptSubmit` | 记录长度受限且经过脱敏的 Prompt 事件 |
| `PostToolUse` | 只有文件或外部状态可能变化时，才记录工具影响 |
| `PreCompact` | 上下文压缩前强制建立检查点 |
| `SubagentStart` / `SubagentStop` | 保留任务边界和有用的子 Agent 结果 |
| `Stop` | 记录最终回答、比较工作区变化，并执行触发门判断 |

安装器一共加入 8 个处理器，是因为 `UserPromptSubmit` 分成项目初始化和事件记录两个 Hook。

### 3. 触发门

Hook 不用正则直接判断业务内容是否重要。脚本里的确定性信号只负责判断“这次是否值得让模型检查”：

- 工作区发生变化
- 用户出现“记住”“以后默认”等明确长期信号
- 上下文即将压缩
- 新会话开始时仍有未处理积压
- 活跃任务超过事件数量或等待时间阈值
- 测试或维护者明确要求强制同步

没有活跃任务、没有长期信号、也没有工作区变化的普通短对话，会在本轮结束后丢弃。这样每句话都可以经过 Hook，但不会每句话都调用模型或产生历史文件。

### 4. 只读 Curator

触发门打开后，`memoryctl.py prepare` 会生成一份事务快照。Hook 再启动一个临时 Codex 进程，并限制为：

- 独立临时 `CODEX_HOME`
- 只读沙箱
- `approval_policy=never`
- 关闭 Hook、memory、个人规则和多 Agent
- 只能输出符合 Schema 的 JSON

Curator 必须给每条来源事件做一种处置：

- `write`：会影响未来工作的长期信息
- `skip`：临时、重复、未确认或可以从真源重建的信息
- `unresolved`：存在冲突或高风险歧义，不能猜

默认模型是低推理强度的 `gpt-5.6-sol`。如果配置允许，模型不可用时可继承当前 task 的模型。

### 5. 确定性提交

Curator 只返回建议，不直接写文件。`memoryctl.py` 会继续检查：

- 每条来源事件是否都有处置结果
- 目标文件是否在本次事务白名单内
- 返回的是完整文件，且没有超过大小限制
- 长期决定和引用是否被偷偷删除
- 项目记忆版本是否仍和 prepare 时一致
- 声称 `write` 时是否真的有文件变化

提交时采用单文件原子替换，最后才推进 manifest 版本。写入中断后，可以根据 commit log 收口或回滚。

## 记忆分层

| 分层 | 用途 | 更新方式 |
| --- | --- | --- |
| `current.md` | 当前有效状态和下一步 | 可以替换过时状态 |
| `spec/` | 稳定项目规则和约束 | 长期保留，按需读取 |
| `tasks/` | 活跃任务和已归档任务 | 按任务隔离 |
| `archive/` | 历史记忆 | 保留用于追溯 |
| `.runtime/` | 待处理事件、事务、锁和审计回执 | 临时、可恢复 |

已经确认的长期记忆不会自动删除。pending 只有在经过校验的 `write` 或 `skip` 成功提交后，才允许清理。

## 空间与压缩

V2 使用软上限提醒，不靠删除长期信息控制空间：

- 单项目运行数据默认软上限 20 MB
- 单项目全部记忆默认软上限 50 MB
- 已完成任务默认保留 90 天热窗口

`gc` 只清理安全的临时产物，并限制失败事务数量。它不会删除 unresolved pending 或长期记忆。按月压缩的目标是“保留来源的前提下做摘要”，不是抹掉历史；v2.0.0 不会主动重排已有 V1 历史。

## 隐私与联网边界

事件和记忆默认保存在项目本地。Curator 真正运行时，本次事务输入会通过配置的 Codex 模型服务处理，其中可能包括 Prompt、精简后的工具影响、最终回答、工作区变化和相关记忆副本。

Hook 会先脱敏常见的 OpenAI、GitHub、AWS、Bearer token、密码和 API key 格式。正则脱敏只能作为防线，不能替代完整的秘密扫描，因此不要把凭据放进 Prompt 或项目记忆。

## 失败时会怎样

- Curator JSON 不合法：保留 pending，不提交。
- 来源没有完全覆盖：拒绝提交。
- 出现 `unresolved`：放弃临时事务，但保留来源交给主 Agent。
- 记忆版本冲突：正式记忆和 pending 都保留。
- 写入中断：根据 commit log 恢复。
- 只有真实且通过校验的写入才显示 `已记录：...`，no-op 保持安静。

安装是否健康使用 `codex-memory-lite doctor`；查看每个项目的运行状态，使用 `codex-memory` Skill 的 `fleet-status`。
